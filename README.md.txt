# Delay Intelligence: Capstone Project

## How to run
1. pip install -r requirements.txt
2. python generate_data.py
3. python src/part_a_clean_eda.py
4. python src/part_b_regression.py
5. python src/part_c_classification.py
6. python src/part_d_segments.py
7. python src/package_model.py
8. python src/predict_delay.py

Note: models/delay_model.pkl is regenerated by running python src/package_model.py.

## Data findings
- Raw dataset contains 1224 shipments, reduced to 1200 unique shipments after deduplication.
- Overall delay rate observed is 23.17% (278 delayed shipments).

## Model results for regression and classification
- Regression: Gradient Boosting achieved the lowest validation RMSE, outperforming baseline, linear regression, and decision tree models.
- Classification: Random Forest with top 7 features achieved strong validation F1 score. Alert threshold was tuned to satisfy recall >= 0.80.

## Operations recommendation
- Escalate hubs: Hubs with high delay rate (>40%) require priority operational escalation.
- The 4 mismatched hubs (HUB07 Kolkata, HUB13 Nagpur, HUB15 Kochi, HUB22 Dehradun) have delay profiles divergent from their historical tier labels, indicating their tier labels should be updated based on their empirical segment.
- The operational alert threshold enables capturing at least 80% of actual delayed parcels proactively.
- K=3 was selected because operations runs exactly three standardized playbooks (Standard, Watch, Escalate), and higher K values split hubs into groups with fewer than 6 hubs which are too small for separate operational routing.

## Production plan
- Pipeline reproducibility and consistency are maintained by sharing pre-processing logic in src/shipment_prep.py.
- Monitoring quantities: Weekly delayed share of delivered parcels, weekly share of parcels flagged, and rolling recall on parcels whose true outcome has materialized.
- The 15-28 September sale window should be monitored against historical sale events rather than regular baseline weeks.

## Limitations
- Synthetic data may not capture real-world anomalous road incidents or complex supply-chain bottlenecks.
- Alert threshold was tuned against a single validation split; continuous recalibration is recommended in production.
- Small number of test delay parcels limits high-resolution confidence intervals on rare edge cases.
